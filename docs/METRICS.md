# Moonlight V1 门店指标口径

M-012 经营复盘只呈现当前数据库能支持的运营事实。所有时间以 UTC 保存，并使用门店 `venues.timezone` 的 IANA 时区解释。

## 周期

“过去 7 天 / 30 天”按门店本地日历日计算，包含本地今天及此前 6 / 29 个自然日，起点为当地午夜，终点为查询时刻，统一采用半开区间 `[start, end)`。DST 切换由 PostgreSQL 的时区规则处理。参与与完成按 Attempt 的 `started_at` 归属同一 cohort；双人房间按 `play_groups.created_at` 归属。

## 指标

| 指标 | 计算 | 解释 |
| --- | --- | --- |
| 参与次数 | 周期内 `started_at` 的 Attempt 行数 | 一名双人参与者一行；完整双人房间通常计两次参与。不代表扫码、到店或独立顾客数。 |
| 完成次数 | 上述同一批 Attempt 中 `status = completed` 的行数 | 新开始尚未完成的参与会暂时降低完成率。 |
| 完成率 | 完成次数 / 参与次数 | 分母为 0 时为 `null`，UI 显示 `—`。不是扫码转化率。 |
| 个人 / 双人分布 | 同一 Attempt cohort 按 `mode` 计数 | 双人参与次数按人次计算。 |
| 双人房间 | 周期内按门店 `venue_id`、`created_at` 计 PlayGroup 行数 | 一个房间只计一次。完整房间须同一组内恰有两条已同意的 duo Attempt，且两条均已完成。完整状态按查询时当前状态计算。 |
| 反馈数、均分、分布 | 反馈关联到周期内 Attempt；按 Feedback 评分汇总 | 反馈可在参与之后提交，因此按开始 cohort 查询时会包括这批参与目前已有的反馈。反馈为自愿提交，样本有自选择偏差。 |
| 题包版本 | Attempt → Publication → ActivityVersion 的实际绑定关系 | 不按当前上架状态过滤；发布新版本或下架后，旧参与仍归属于旧的不可变版本。 |

SQL 先分别聚合 Attempt、PlayGroup、Feedback 和版本分支，再组合结果。每个门店查询分支都带门店范围，不联接 Submission 明细，不向页面返回个人 Attempt、评分、答案、令牌或桌码。反馈表的每 Attempt 唯一约束使每位参与者最多一条评分。

## 不支持的指标

当前没有可信的扫码打开事件、持久顾客身份、收银订单或营收来源，故不展示扫码 PV/UV、扫码转化、独立顾客数、留存/复购、到店人数、收入增长、ROI 或 AI 归因。Attempt 数量不能作为上述指标的替代值。
